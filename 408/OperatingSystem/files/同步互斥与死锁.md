第 2 章把"一个进程在 CPU 上怎么跑"讲清楚了。但现实里 OS 同时养着几十上百个进程，它们**会互相打架**——抢同一个变量、抢同一台打印机、互相等对方先动手。这章就是讲**怎么让并发的进程不互相打成一团**。

## 3.1 并发进程的基本错误

### 顺序 vs 并发

**顺序程序设计**：一个程序从头执行到尾，前一步没做完后一步不开始。
- 特点：环境封闭、过程可重现、结果确定

**并发程序设计**：多个程序段在时间上重叠执行。
- 单核 CPU：宏观并发，微观仍是串行
- 多核：才真正"同时"

### 并发进程分两类

| 类型 | 含义 | 是否有问题 |
| --- | --- | --- |
| 无关并发 | 各进程操作不同变量集 | 安全，结果与执行顺序无关 |
| 交往并发 | 共享变量、互相影响 | **可能出错**，本章重点 |

**Bernstein 条件**（无关并发的判定）：
- `R(p)` = 进程 p 读的变量集；`W(p)` = 进程 p 写的变量集
- 两个进程"无关"等价于：`R(p1)∩W(p2)=∅` **且** `R(p2)∩W(p1)=∅` **且** `W(p1)∩W(p2)=∅`
- 通俗：**A 写的 B 不读、B 写的 A 不读、A B 不同时写**

### 与时间有关的错误（本章核心痛点）

#### 错误一：结果不唯一 — 飞机票售票问题

两个售票点同时卖第 j 班次，Aj=1（只剩 1 张），T1、T2 同时跑：
- 各自读到 X1=X2=1 → 都判 ≥1 → 都减到 0 → 都"输出一张票" → **卖了两张票，但库存只有 1 张**！

**根因**：`X=X+1` 不是原子操作，被编译成"读-改-写"3 步，两个进程把 3 步交错执行就出错。这就是著名的 **lost update**（丢失更新）。

#### 错误二：永远等待 — 内存申请归还问题

两个进程各自申请超过剩余内存的资源 → 都进等待队列 → 别人不还就一直等 → **互相饿死**。

### 进程交往的两种关系

| 关系 | 别名 | 本质 |
| --- | --- | --- |
| **竞争**（互斥） | 间接制约 | 抢独占资源（打印机、共享变量） |
| **协作**（同步） | 直接制约 | 协调先后次序（生产先于消费） |

**互斥伴生的两个病**：
- **死锁**：互相等对方释放资源 → 永远卡住
- **饥饿**：某进程一直被忽略 → 等到天荒地老

## 3.2 临界资源与临界区

### 三个核心名词

- **临界资源**（critical resource）：一次只能被一个进程使用的共享资源
- **临界区**（critical section / region）：进程中**访问临界资源的那段代码**
- **互斥**（mutual exclusion）：一次只让一个进程进自己的临界区

### 临界区调度的 4+1 原则（必背）

| 原则 | 含义 |
| --- | --- |
| **互斥使用** | 一次最多一个进程在临界区 |
| **有空让进** | 临界区空闲时，请求进入的应立即进入 |
| **忙则等待** | 已有进程在内，其他进程必须等 |
| **有限等待** | 等待时间有上限，不能无限期等 |

口诀：**互斥使用、有空让进、忙则等待、有限等待**。

### 临界区代码骨架

```
while (1) {
    进入区;     // entry section: 检查能不能进
    临界区;     // critical section
    退出区;     // exit section: 标记我出来了
    其余区;     // remainder section
}
```

## 3.3 实现互斥的硬件方法

### 方法一：关中断

```
while (1) {
    屏蔽中断;       // 进入区：不让任何中断打断我
    临界区;
    恢复中断;       // 退出区
    其余区;
}
```

**3 个致命缺点**：
1. **代价高**：所有中断都被屏蔽，影响并发性
2. **不安全**：把"关中断"权交给用户进程，普通进程可以借此"霸占" CPU
3. **不适用多 CPU**：进程只能关本 CPU 的中断，别的 CPU 上的进程照样能进临界区

### 方法二：硬件指令（TestAndSet / Swap）

CPU 提供一条**原子指令**，把"读+改+写"压成不可分割的一步，**执行时锁内存总线**。

**TestAndSet（TS 指令）**：
```
bool TS(bool &x) {       // 硬件原子
    if (x) {             // 如果资源可用
        x = false;       // 占住
        return true;     // 我抢到了
    } else {
        return false;    // 没抢到
    }
}
```

**Swap 指令（对换指令）**：
```
void SWAP(bool &a, bool &b) {  // 硬件原子
    bool temp = a;
    a = b;
    b = temp;
}
```

## 3.4 信号量与 PV 操作

### 信号量定义

信号量 S 是一个**整型变量**，只能通过 P 和 V 两个原子操作访问：
- S > 0：表示有 S 个可用资源
- S = 0：表示无可用资源
- S < 0：表示有 |S| 个进程在等待

### P 操作（申请资源，荷兰语 Proberen = 测试）

```
P(S) {
    S = S - 1;
    if (S < 0) {
        进程进入等待队列，阻塞;
    }
}
```

### V 操作（释放资源，荷兰语 Verhogen = 增加）

```
V(S) {
    S = S + 1;
    if (S <= 0) {
        从等待队列唤醒一个进程;
    }
}
```

### 两种信号量

| 类型 | 定义 | 特点 |
| --- | --- | --- |
| **整型信号量** | S 只取整数值 | 忙等（S≤0 时循环测试） |
| **记录型信号量** | S 值 + 等待队列 | 阻塞等待（不浪费 CPU） |

### PV 操作经典应用

**用于互斥**（一个信号量，初值 1）：
```
P(mutex);    // 进入区
临界区;
V(mutex);    // 退出区
```

**用于同步**（一个信号量，初值 0）：
```
// 进程 A（先执行）
V(sync);     // 我做完了，通知你

// 进程 B（后执行）
P(sync);     // 等你做完我再开始
```

## 3.5 PV 操作铁律（必背）

1. **P 自己等的，V 别人等的** — 谁触发事件谁 V
2. **同步 P 在前，互斥 P 在后** — 避免"抱锁睡觉"
3. **互斥 P/V 在同一进程内成对** — 不能漏写 V

## 3.6 经典同步问题（必考）

### 3.6.1 生产者-消费者问题

**单缓冲区**：
```
int mutex = 1;  // 互斥信号量
int empty = 1;  // 缓冲区空位
int full = 0;   // 缓冲区数据

// 生产者
P(empty);
P(mutex);
放入缓冲;
V(mutex);
V(full);

// 消费者
P(full);
P(mutex);
取出数据;
V(mutex);
V(empty);
```

**多缓冲区（n 个缓冲区）**：
```
int mutex = 1;  // 互斥信号量
int empty = n;  // 空缓冲区数
int full = 0;   // 满缓冲区数
int in = 0, out = 0;  // 指针

// 生产者
P(empty);
P(mutex);
buffer[in] = item;
in = (in + 1) % n;
V(mutex);
V(full);

// 消费者
P(full);
P(mutex);
item = buffer[out];
out = (out + 1) % n;
V(mutex);
V(empty);
```

### 3.6.2 读者-写者问题

**读者优先**：写者可能饥饿

```
int readcount = 0;  // 当前读者数
int mutex = 1;      // 保护 readcount
int rw = 1;         // 读写互斥

// 读者
P(mutex);
readcount++;
if (readcount == 1) P(rw);  // 第一个读者锁住写者
V(mutex);
读数据;
P(mutex);
readcount--;
if (readcount == 0) V(rw);  // 最后一个读者释放写者
V(mutex);

// 写者
P(rw);
写数据;
V(rw);
```

### 3.6.3 哲学家进餐问题

**避免死锁的 4 种方法**：

| 方法 | 破坏条件 |
| --- | --- |
| 资源序号法（先小后大） | ④ 循环等待 |
| 限制最多 4 人同时拿叉 | ④ 循环等待（变相） |
| 同时拿两叉或一根都不要 | ③ 占有并等待 |
| 每人一双自己的叉子 | ① 互斥 |

## 3.7 死锁

### 死锁定义

一组进程处于死锁状态——若进程集合中每个进程都在等待"只能由该集合中的另一个进程才能引发的事件"。

### 死锁的 4 个必要条件（Coffman 1971）

| # | 条件 | 含义 |
| --- | --- | --- |
| 1 | **互斥** | 资源一次只能被一个进程使用 |
| 2 | **不可抢占** | 资源只能由占用进程主动释放 |
| 3 | **占有并等待** | 进程已占资源，请求新资源时不放弃已占 |
| 4 | **循环等待** | 存在进程链，每个等待下一个占用的资源 |

口诀：**互斥/不抢/占等/循环**——4 个全有才死锁，破坏任一个就避免死锁。

### 死锁处理策略

| 策略 | 方法 | 说明 |
| --- | --- | --- |
| **死锁预防** | 破坏四条件之一 | 静态分配（破坏占等）、层次分配（破坏循环） |
| **死锁避免** | 银行家算法 | 分配前检查是否安全，不安全则拒绝 |
| **死锁检测** | 资源分配图检测 | 允许死锁发生，发现后解除 |
| **死锁解除** | 撤销进程/回退 | 中止死锁进程或回退到检查点 |

### 银行家算法（Dijkstra 1965）

**算法步骤**：
```
1. 初始化：Work ← Available, Finish[i] ← false (所有 i)
2. 找 Finish=false 且 Need[i] ≤ Work 的进程：
   - 找到 → Work ← Work + Allocation[i], Finish[i] ← true，回 2
   - 找不到 → 跳 3
3. 检查 Finish 数组：
   - 全为 true → 安全
   - 有 false → 不安全
```

口诀：**找得到就走、找不到就停、停下后看完没完**

**典型例题**：系统资源 = 12，3 个进程：
```
P1: Max=10, Alloc=5, Need=5
P2: Max=4,  Alloc=2, Need=2
P3: Max=9,  Alloc=2, Need=7
Available = 12-9 = 3

推演：Work=3 → P2(Need=2) ✓ → Work=5
     → P1(Need=5) ✓ → Work=10
     → P3(Need=7) ✓ → Work=12
安全序列：P2 → P1 → P3
```

### 死锁 vs 不安全状态

**死锁 ⊂ 不安全 ⊂ 全状态**
- **安全**：存在安全序列让所有进程完成
- **不安全**：找不到安全序列，**有死锁风险**但不一定死锁
- **死锁**：实际发生进程互相等待

## 考点总结

1. **PV 操作三步法**：画关系 → 设信号量 → 写 PV
2. **PV 铁律**：P 自己等的，V 别人等的；同步 P 在互斥 P 前
3. **生产者-消费者**：单缓冲/多缓冲，信号量设置
4. **读者-写者**：读者优先、写者饥饿
5. **哲学家进餐**：4 种避免死锁的方法
6. **死锁四条件**：互斥/不抢/占等/循环
7. **银行家算法**：安全序列判断（必考大题）
8. **死锁处理策略**：预防/避免/检测/解除
