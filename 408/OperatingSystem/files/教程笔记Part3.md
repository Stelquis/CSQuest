## 第 6 章 6.6 节 死锁（书 p230-p239）

### 6.6.1 死锁的产生

**死锁定义**：一组进程处于死锁状态——若进程集合中每个进程都在等待"只能由该集合中的另一个进程才能引发的事件"，则称这组进程或系统发生了死锁。

形式上：n 个进程 P1,…,Pn，每个 Pi 因申请不到资源 Rj 而处于等待状态，而 Rj 又被 Pi+1 占有，Pn 申请的资源被 P1 占有——形成永无解的循环等待。

**死锁举例**（按死锁起因分类）：

- **例 3 — 竞争资源**：进程 P 持有读卡机申请打印机、Q 持有打印机申请读卡机 → 互相等
- **例 4 — PV 操作使用不当**：Q1 = P(s1); P(s2); …，Q2 = P(s2); P(s1); …，s1=s2=1 初值。Q1 拿到 s1 后切到 Q2，Q2 拿到 s2，再各自申请对方信号量 → 死锁。**这种死锁不涉资源**，是 P 操作排序不当造成
- **例 5 — 同类资源分配不当**：m 个资源被 n 个进程共享，每个进程要求 K 个，且 m < n·K。轮流分配第一轮后资源耗尽，第二轮全部阻塞
- **例 6 — 临时性资源使用不加限制**：P1 等 P3 信件 S3 才发 S1；P2 等 P1 信件 S1 才发 S2；P3 等 P2 信件 S2 才发 S3 → 循环等待

### 6.6.2 死锁的防止

**Coffman（1971）总结的 4 个必要条件**：

| # | 条件 | 含义 |
| --- | --- | --- |
| 1 | **互斥**（mutual exclusion） | 资源任一时刻仅一个进程独占 |
| 2 | **占有和等待**（hold and wait） | 进程因申请资源得不到满足而等待时不释放已占资源 |
| 3 | **不剥夺**（no preemption） | 资源只能由占用进程主动释放 |
| 4 | **循环等待**（circular wait） | 存在一个循环等待链 |

**只要破坏 4 个条件之一即可防止死锁**。

**破坏方法**：

| 方法 | 破坏条件 | 说明 |
| --- | --- | --- |
| **SPOOLing 技术** | ① 互斥 | 用共享磁盘模拟独占设备 |
| **剥夺式调度** | ③ 不剥夺 | 申请未获时主动释放已占资源，重新一起申请 |
| **静态分配策略** | ② 占有和等待 | 进程执行前一次申请全部资源，全部满足才开始 |
| **层次分配策略** | ④ 循环等待 | 资源分多个层次，进程只能按层次顺序申请 |

### 6.6.3 死锁的避免 — 银行家算法（Dijkstra 1965）

**思想**：在为申请者分配资源前先测试系统状态，若分配会产生死锁则拒绝；否则分配。

**经典例题**（教材 p236）：

设系统有 3 个进程 P、Q、R，共 10 个同类资源。当前分配状态：

| 进程 | 已占 | 还需 |
| --- | --- | --- |
| P | 4 | 4 |
| Q | 2 | 2 |
| R | 2 | 7 |

剩余资源 = 10 - 4 - 2 - 2 = 2。

- 若给 P 或 R：后续任何进程申请资源都得不到满足 → 可能死锁
- 若给 Q：Q 最多再需 2，2 个剩余可以满足 → Q 可执行结束并归还其全部 4 个资源。系统得到 4 个资源后情况为：P(4,4), R(2,7)。此时可满足 P 的 4 个申请，但 R 仍无法满足（4-4=0 < 7）→ R 申请会被拒绝

**缺点**：保守、资源利用率低；每次分配前都要检查每个进程对各类资源的最大需求，**时间开销大**。

### 6.6.4 死锁的检测与解除

**两张表格法**：
- 占用资源表：记录每个进程占用了哪些资源
- 等待资源表：记录每个被阻塞进程在等什么资源

**Warshall 传递闭包算法**：
```
for (int k = 1; k <= n; k++)
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            bij = bij ∨ (bik ∧ bkj);
```

若对角线存在 1，则说明存在循环等待 → 死锁。

**死锁解除方法**：
- 结束所有进程并重启 OS（代价大）
- 撤销所有死锁进程，重新启动它们
- 设置校验点（checkpoint）回退
- 中止一个卷入死锁的进程，再重新执行

### 6.6 本章小结

并发进程间存在两种基本关系：**竞争**（互斥）和**协作**（同步）。

- 并发进程中与互斥共享变量有关的程序段称为**临界区**
- **信号量与 PV 操作**是一种有效的临界区管理方法
- 使用信号量与 PV 时，对共享资源的管理分散在各进程中——为统一管理，引入**管程**方法
- 经典问题：生产者-消费者、苹果-橘子、读者-写者、哲学家就餐
- **死锁**：一组并发进程因等待其他进程占有资源而永远不能向前推进的僵化状态
- 三个解决策略：死锁防止、死锁避免、死锁检测和解除

## 第 7 章 网络环境下的操作系统（书 p247-p302）

本章主线：网络体系结构 → 网络/分布式 OS → 云计算/虚拟化 → 移动终端 OS → 网络安全 → 区块链。

### 7.1 计算机网络与网络操作系统

#### 7.1.1 网络体系结构

**ARPANET** — 计算机网络发展里程碑，由通信子网和资源子网两层结构组成，含纠错、路由选择、分组交换、流量控制等。

**OSI-RM**（开放系统互联参考模型，ISO 1980 年代）— 7 层标准化通信体系：
- 物理层 / 数据链路层 / 网络层 / 传输层 / 会话层 / 表示层 / 应用层

**TCP/IP**（实际工业标准）— 1983 年起在 UNIX BSD 上使用：
- 最知名的两层：传输层 TCP + 网络层 IP
- 三层结构：应用层、传输层 TCP、网际层 IP

#### 7.1.2 网络操作系统（NOS）

**典型特征**：① 硬件独立性 ② 多用户支持 ③ 支持网络实用程序 ④ 多种客户端支持 ⑤ 单一逻辑目录服务 ⑥ 多种增值服务 ⑦ 可操作性

**三种模式**：

| 模式 | 特征 | 代表 |
| --- | --- | --- |
| **集中模式** | 一台主机+若干终端，处理和控制集中 | UNIX |
| **C/S（客户机/服务器）** | 服务器集中资源管理，客户机有独立处理能力 | NetWare、Windows NT |
| **P2P（对等）** | 每台机兼客户机和服务器，无中央控制 | NetWare Lite、Windows for WorkGroup |

#### 7.1.3 网络文件系统（NFS）

**Sun NFS** — 构建于 TCP/IP，广泛用于 UNIX 及其他 POSIX 系统。

**关键数据结构 — VFS（虚拟文件系统）层**：每个打开的文件对应一个 v 节点（v-node）。v 节点指针指向：
- 客户机代码中的 r 节点（远程节点）→ 表示远程文件
- 本地操作系统的 i 节点（i-node）→ 表示本地文件

**关键调用**：
- `mount`：分析远程目录、建立联系，请求得到目录的文件句柄
- `open`：打开远程文件得到远程文件描述符
- `read/write`：通常以较大块（**8 KB**）传输

### 7.2 分布式操作系统

#### 7.2.1 概念与特点

分布式操作系统建立在"松散耦合的多台计算机"上，但本身是**紧密耦合软件**——它把整个系统作为一个整体管理，进程可以在任意节点执行而对用户透明。

**与网络 OS 的区别**：网络 OS 强调每台机器独立操作系统，仅协议互联；分布式 OS 强调统一系统映像。

#### 7.2.2 分布式进程通信

需解决：① 目标进程寻址 ② 通信原语设计

**寻址法**：① 机器号+进程号 ② 广播寻址 ③ 名字服务器寻址

**同步/异步通信原语**：基本形式 `Send(P, Message)`、`Receive(Q, Buffer)`

### 7.3 云计算与虚拟化

**云计算**：通过网络按需提供可配置计算资源（网络、服务器、存储、应用和服务）的模式。

**虚拟化技术**：
- **服务器虚拟化**：一台物理服务器运行多个虚拟机
- **存储虚拟化**：将多个物理存储设备抽象为一个逻辑存储池
- **网络虚拟化**：将物理网络资源抽象为多个虚拟网络

**容器 vs 虚拟机**：
- 容器：共享宿主机内核，轻量，秒级启动
- 虚拟机：包含完整 OS，重量，分钟级启动

### 7.4 移动终端 OS

**主要移动 OS**：Android（基于 Linux）、iOS（基于 Darwin/XNU）

**移动 OS 特点**：
- 触控交互为主
- 电源管理（省电）
- 传感器集成（GPS、加速度计、陀螺仪）
- 应用沙箱机制

### 7.5 网络安全

**安全威胁**：病毒、蠕虫、木马、DoS/DDoS、中间人攻击、SQL 注入

**安全机制**：
- 身份认证（口令、生物特征、双因素）
- 访问控制（DAC、MAC、RBAC）
- 加密（对称加密、非对称加密）
- 数字签名与证书

### 7.6 区块链

**区块链**：去中心化、不可篡改的分布式账本技术。

**核心特征**：
- 去中心化：无中心服务器
- 不可篡改：每个区块包含前一个区块的哈希
- 共识机制：工作量证明（PoW）、权益证明（PoS）
