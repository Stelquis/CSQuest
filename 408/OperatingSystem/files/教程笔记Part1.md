## 第一章 计算机操作系统概述

### 引入：什么是操作系统

**原书定义**：操作系统（operating system, OS）是计算机系统中最重要的系统软件，它统一管理计算机系统的硬件资源与信息资源，控制与调度上层软件的执行并为其提供易于使用的接口。

**日常类比**：操作系统好比一个酒店总管。客人（应用程序）来住店，不会直接去找清洁工、厨师、电工沟通，全部通过总管登记、调度。总管的两个职责：①管理资源（房间、餐食、热水）②对外提供易用的服务接口（前台办理）。

### 1.1 计算机系统

#### 1.1.1 计算机系统概述

**计算机技术的发展四阶段**：

| 代次 | 时期 | 主要器件 | 关键特征 |
| --- | --- | --- | --- |
| 第一代 | 1946-1957 | 电子真空管 | 速度慢、存储量小、体积大；尚无 OS；手工操作 |
| 第二代 | 1958-1964 | 晶体管 | 体积小、寿命长、功耗低；批处理控制系统、FORTRAN |
| 第三代 | 1965-1977 | 集成电路 | 多道程序设计成为主流；磁盘出现；OS 日臻成熟 |
| 第四代 | 1978-至今 | 大规模/超大规模集成电路 | 微机化、网络化、智能化；移动计算兴起 |

**计算机系统的组成**：硬件 + 软件。硬件是软件运行的物质基础，软件能够充分发挥硬件潜能并扩充硬件功能。

**计算机系统的层次结构**：从底向上依次是：
- 计算机硬件
- 系统软件层（操作系统、实用程序、语言处理程序、数据库管理系统）
- 支撑软件层（接口软件、工具软件、环境数据库）
- 应用软件层（财务系统、航空订票、上网浏览、电子商务…）
- 用户

#### 1.1.2 计算机硬件系统

计算机硬件系统是借助电、磁、光、机械等原理构造的各种物理部件的有机结合，包括：处理器、存储器、I/O 控制系统及外围设备。

#### 1.1.3 计算机软件系统

计算机软件系统包括各类程序和文件，用于指挥计算机系统按指定要求进行协同工作，包括系统软件、支撑软件和应用软件，其中最关键的系统软件是**操作系统**和**语言处理程序**。

### 1.2 计算机操作系统

#### 1.2.1 计算机操作系统技术的发展

- **手工操作阶段**（第一代）：用户用开关、按钮、亮灯直接控制计算机
- **机械化批处理阶段**（第二代）：操作员把多道作业组织成"作业说明书 + 程序数据"，排队执行
- **多道程序设计的诞生**（第三代起）：让多道程序同时进入主存，使外设和 CPU 充分并行
  - 关键技术支撑：I/O 中断 + 磁盘
  - 1960 年磁盘出现使多道程序执行成为可能，操作系统正式诞生

#### 1.2.2 操作系统及其分类

**操作系统定义**：计算机系统中最基础的系统软件，统一管理软硬件资源，控制程序执行，改善人机界面，合理组织计算机工作流程，为用户使用计算机提供良好的运行环境。

**三大经典 OS 对比**：

| 类型 | 特点 | 代表 |
| --- | --- | --- |
| **批处理 OS** | 作业 = 程序 + 数据 + 作业说明书。预先排入作业队列，自动连续处理 | UNIX Shell、Windows .bat |
| **分时 OS** | 多个联机用户同时使用，每人一个终端，时间片轮流分配 | Unix、Linux |
| **实时 OS** | 要求计算机在严格时限内响应外部事件 | VxWorks |

### 1.3 深入观察操作系统

教材通过 6 个角度刻画 OS：资源管理、程序控制、操作控制、人机交互、程序接口、系统结构。

#### 1.3.1 资源管理的角度

**OS 面对的难题**：
1. 物理资源在硬件实现上的复杂性 → 用户几乎不可能直接使用，需 OS 提供机制封装细节
2. 物理资源有限而竞争资源的应用进程众多 → 必须解决资源数量不足和如何合理分配两个问题

**资源分配三种方式**：
- **静态分配**：进程运行前一次性拿到全部独占资源。资源利用率低
- **动态分配**：使用资源前临时申请。可能因资源竞争产生**死锁**
- **资源抢占式分配**：可剥夺正在使用的资源。被抢的进程需要执行回退

**资源管理三大基本技术**：复用、虚拟、抽象（详见 Ch1 章节内容）

#### 1.3.2 程序控制的角度

**关键例题：CPU 利用率**

某数据问题：从输入机输入 78 ms，CPU 计算 52 ms，结果存磁盘 20 ms，循环至处理完毕。

- **单道**：CPU 利用率 = 52 / (78 + 52 + 20) ≈ 35%
- **两道程序同时进入主存**：CPU 利用率 = (52 + 42) / 150 ≈ 63%

结论：多道程序设计能显著提高 CPU 利用率。

#### 1.3.3-1.3.5 操作控制、人机交互、程序接口

**操作控制方式**：命令解释程序（命令行）、GUI 图标点击、批处理命令文件

**人机交互 4 类**：CLI、GUI、触摸界面、模式识别界面

**系统调用 vs 函数调用**（重要对比）：

| 比较点 | 函数调用 | 系统调用 |
| --- | --- | --- |
| 调用方式 | 静态调用，与调用者同一程序内 | 动态调用，服务例程位于 OS 中 |
| 运行栈 | 用户栈 | 内核栈（需经陷阱机制从用户态转内核态） |
| 提供方 | 编程语言 | 操作系统 |
| 升级影响 | 需重新编译链接 | 升级修改与调用程序无关 |

#### 1.3.6 系统结构的角度

OS 通常采用分层、模块化、微内核等结构来管理复杂度。

## 第二章 处理器管理

### 2.1 处理器

#### 2.1.1 处理器与寄存器

**处理器（CPU）的部件构成**：
- **算术逻辑单元（ALU）**：负责运算
- **控制单元**：核心是**指令译码器（ID）**，负责解释指令的执行
- **指令寄存器（IR）**：存放当前指令
- **程序计数器（PC）**：指向下一条要执行的指令的主存地址
- **标志寄存器**：汇总指令执行结果
- **主存地址寄存器（MAR）** 和 **主存数据寄存器（MDR）**：访问主存的桥梁

**关键标志位**：中断位、中断允许位、中断屏蔽位、处理器模式位、主存保护位

**程序状态字（PSW）**：记录程序执行的动态行为，包括程序计数器、指令寄存器、条件码、中断位、处理器模式位等。是 OS 切换进程时必须保存/恢复的关键现场信息。

#### 2.1.2 指令与处理器模式

**处理器模式**：
- **内核态（系统态/管态）**：OS 例程运行，可执行所有指令
- **用户态（目态）**：应用程序运行，只能执行非特权指令

**两类栈**：
- **用户栈**：在用户进程空间中，保存子程序间互相调用的参数、返回值、返回点和局部变量
- **核心栈（系统栈/内核栈）**：在 OS 内核空间中，保存中断现场、OS 函数调用的参数返回值

### 2.2 中断

#### 2.2.1 中断的概念

**原书定义**：中断机制是现代计算机系统的重要组成部分。每当应用程序执行系统调用、要求获得 OS 服务、I/O 设备报告传输情况、或产生各种内部和外部事件时，都要通过中断机制产生中断信号并启动 OS 内核工作。**可以说操作系统是由中断驱动的**。

#### 2.2.2 中断源

**I/O 中断的处理原则**：
- I/O 操作正常结束：本进程置就绪态，让等待的下一进程占用设备并启动数据传输
- I/O 操作发生故障：向设备发送命令索取状态字，分析故障原因，复执或人工干预
- I/O 操作发生异常：分析情况，采取相应措施并向操作员报告

**外部中断事件**：
- 时钟中断：计时
- 间隔时钟中断：时间片到，被中断进程让出 CPU 进入就绪队列（**分时系统/时间片轮转的硬件支撑**）
- 设备报告与结束中断：调整设备表
- 键盘/鼠标信号中断：根据信号反应
- 关机/重启动中断：写回文件、停止设备与 CPU

#### 2.2.3 中断系统

**中断系统**：响应和处理中断的系统，包括硬件子系统（完成中断响应）和软件子系统（完成中断处理）。

**多重中断**（中断嵌套）：OS 在处理某中断过程中又发生新的中断，会保护被中断的处理程序现场，转向新中断处理程序。

### 2.3 进程管理

#### 2.3.1 进程及其状态

**进程的概念（核心定义）**：
- 从原理角度看：进程是支持程序执行的机制，是程序在数据集合上的一次执行过程
- 从实现角度看：进程是进程控制块（PCB）描述的程序运行活动

**进程三态模型**：
- **就绪态**：进程已具备运行条件，等待 CPU
- **运行态**：进程正在 CPU 上执行
- **阻塞态**：进程因等待 I/O 或事件而暂停

**进程五态模型**：新建态 → 就绪态 ↔ 运行态 → 终止态
                    ↑        ↓
                  阻塞态

#### 2.3.2 进程控制块（PCB）

**PCB 的作用**：PCB 是进程赖以存在的标志，是进程在 OS 中的唯一标识。

**PCB 的内容**：
- 标识信息（进程 ID、用户 ID）
- 现场信息（寄存器、PC、PSW）
- 调度信息（状态、优先级、等待时间）
- 资源信息（占用内存、打开文件）
- 链接信息（指向下一个 PCB 的指针）

**PCB 组织方式**：链表（就绪队列、阻塞队列等）和索引表

#### 2.3.3 进程切换

**进程切换步骤**：
1. 保存处理器现场（寄存器、PC、PSW）到当前进程 PCB
2. 更新当前进程 PCB 的状态
3. 将当前进程 PCB 移入对应队列
4. 选择另一个进程执行
5. 从新进程 PCB 恢复处理器现场
6. 继续执行新进程

#### 2.3.4 进程控制

**原语（Primitive）**：OS 内核中用于完成特定功能的不可中断过程。

**进程控制原语**：
- 创建原语：创建 PCB，分配资源
- 撤销原语：回收资源，撤销 PCB
- 阻塞原语：将进程从运行态改为阻塞态
- 唤醒原语：将进程从阻塞态改为就绪态

### 2.4 线程

**线程的概念**：线程是进程内的一个执行单元，是 CPU 调度的基本单位。

**线程与进程的比较**：

| 比较 | 进程 | 线程 |
| --- | --- | --- |
| 资源拥有 | 独立资源空间 | 共享进程资源 |
| 切换代价 | 大 | 小 |
| 通信 | 需 IPC | 可直接读写 |
| 调度 | 进程调度 | 线程调度 |

**用户级线程（ULT）**：
- 用户空间线程库管理，内核不知
- 切换快（不陷入内核）
- 一个线程阻塞 → 整个进程阻塞

**内核级线程（KLT）**：
- 内核管理，内核知道每个线程
- 切换慢（需陷入内核）
- 一个线程阻塞 → 只阻塞该线程
- 可多核并行

### 2.5 处理器调度

**三级调度**：
- 高级调度（作业调度）：从外存作业池选入内存
- 中级调度（对换调度）：进程挂起/对换
- 低级调度（进程调度）：从就绪队列选进程上 CPU

**调度算法评价指标**：CPU 利用率、吞吐量、周转时间、带权周转时间、响应时间

**七种调度算法**：
1. FCFS（先来先服务）
2. SJF（短作业优先）
3. RR（时间片轮转）
4. HRRF（最高响应比优先）
5. 优先级调度
6. 多级反馈队列
7. 多级队列

## 第三章 存储管理（前段）

### 3.1 存储管理基础

**存储管理基本功能**：
1. 主存分配/回收
2. 地址转换/重定位
3. 存储保护/共享
4. 存储扩充

**地址空间概念**：
- **逻辑地址**：程序使用的地址，从 0 开始
- **物理地址**：主存中实际地址，唯一
- **地址重定位**：将逻辑地址转换为物理地址

### 3.2 连续分配方式

**单一连续分配**：内存只装一个用户程序 + OS

**固定分区分配**：预先切好 N 个固定大小分区
- 优点：管理简单
- 缺点：内部碎片

**动态分区分配**：进程来后再切
- 优点：无内部碎片
- 缺点：外部碎片

**分配算法**：首次适应、下次适应、最佳适应、最坏适应

### 3.3 覆盖与对换

**覆盖技术**：程序内部分段，主程序常驻，不常用子程序按需替换

**对换技术**：低优先级进程整个写到磁盘，腾内存给高优先级进程

### 3.4 分页存储管理

**基本概念**：
- 页（Page）：逻辑空间的一块
- 页框（Frame）：物理内存的一格
- 页表：页号 → 页框号的映射表

**地址转换公式**：
```
页号 p = INT[A / L]
页内偏移 d = A mod L
物理地址 = 页框号 × L + d
```

**快表（TLB）**：高速缓存，存储最近使用的页表项，加速地址转换

**多级页表**：页表本身也分页，按需装入，节省内存

### 3.5 分段存储管理

**段式管理的优点**：
- 方便编程：每个段独立编址
- 方便共享：代码段可被多个进程共享
- 方便保护：每个段可设读写权限
- 方便动态增长：堆栈段可动态扩张

**地址转换**：物理地址 = 段基址 + 段内偏移
