## 0. 章节导览

操作系统四大件管理对象之首是 **CPU**——所有程序最后都要在 CPU 上跑，谁先跑、谁后跑、跑多久、被打断了怎么办，都是这章的事。

## 2.1 处理器的硬件结构

### 寄存器（CPU 内部的小型仓库）

**类比**：CPU 是厨师，主存是冰箱。寄存器就是厨师手边的"小调料盘"——容量小（几十个），但拿放飞快（远快于跑去冰箱）。

Intel x86 寄存器分类：

| 类别 | 例子 | 用途 |
| --- | --- | --- |
| 通用寄存器 | EAX、EBX、ECX、EDX | 临时存数 |
| 指针/变址 | ESP、EBP、ESI、EDI | 栈指针、数组下标 |
| 段选择符 | CS、DS、SS、ES、FS、GS | 内存分段 |
| 指令/标志 | EIP（指令指针）、EFLAGS（标志位） | 指向"下一条指令"+ 状态 |
| 控制寄存器 | CR0~CR3 | 系统级控制 |

寄存器组成了"**处理器现场**"——切换进程时要把这些值整组保存起来。

### 指令系统

每台机器的"机器指令集合"叫**指令系统**，分 5 类：
- 数据处理类（算术/逻辑）
- I/O 类（启动外设）
- 寄存器-存储器交换类
- 转移类（跳转）
- 处理器控制类

**关键二分：特权指令 vs 非特权指令**
- **特权指令**：只有 OS 核心才能用。例：启动 I/O、设时钟、改中断屏蔽位、加载 PSW
- **非特权指令**：用户程序也能用

## 2.2 处理器状态（管态 / 目态）

### 双态机制

| 状态 | 别名 | 能干什么 |
| --- | --- | --- |
| **管态**（核心态/特态/内核态） | supervisor mode | 全部指令 + 所有资源 |
| **目态**（用户态/常态） | user mode | 只能执行非特权指令 |

CPU 怎么知道自己当前是哪种？→ 看 **PSW（程序状态字）** 里的状态位。

### 状态切换（必考）

**目态 → 管态**（只有这两条路！）：
- **系统调用**：用户程序主动请求 OS 服务（如 `read()`）
- **中断 / 异常**：被动打断

**管态 → 目态**：执行特权指令 `iret`（Intel x86）加载 PSW，把控制权交回应用进程。

### Intel x86 的 4 个保护级

Pentium 实际有 0/1/2/3 四级，0 级权限最高：
- 0 级：OS 内核（I/O、内存管理）
- 1 级：系统调用处理程序
- 2 级：共享库
- 3 级：用户程序（保护最少）

实际上 Windows 和 Linux 只用 0 级和 3 级（精简方案）。

### 用户栈 vs 核心栈

- **用户栈**：在用户进程空间里，存函数调用的参数/返回值/局部变量
- **核心栈**：在 OS 空间里，存中断现场 + OS 内部函数调用

### PSW（程序状态字）

PSW 是 CPU 里的一个寄存器，记录"当前程序的状态"。包括：
- **程序基本状态**：PC（程序计数器）、条件码、处理器状态位（管/目）
- **中断码**：当前发生的中断事件
- **中断屏蔽位**：哪些中断当前不响应

每个进程都有自己的 PSW，进程切换时 PSW 也要换。

## 2.3 中断机制

### 为什么要有中断

**类比**：你在做菜（执行用户程序），快递员按门铃（外设事件）。你不能让锅一直转着不管门铃，也不能盯着门一动不动不做菜——所以需要一个"按了铃我立刻应一下，处理完回来继续做菜"的机制。这就是**中断**。

**中断定义**：程序执行时遇急事，**暂停现行程序 → 转去执行事件处理程序 → 完事返回原处或调度其他程序**。

### 中断系统组成

- **中断装置**（硬件）：发现中断源 → 提请求 → 保护现场 → 启动处理程序
- **中断处理程序**（软件）：处理事件 → 恢复现场

### 中断分类（重点区分）

| 维度 | 外中断（中断/异步中断） | 内中断（异常/同步中断） |
| --- | --- | --- |
| 来源 | 处理器**外**的信号 | 处理器**内**，与当前指令相关 |
| 例子 | 时钟、键盘、网卡 | 除零、缺页、非法访问 |
| 触发时机 | 与现行指令无关 | 现行指令引起 |
| 响应时机 | 两条指令**之间** | 指令执行**期间**也可响应 |
| 服务对象 | 通常**不是**当前进程 | 就是当前进程 |
| 能否阻塞 | **不能阻塞** | 可以阻塞 |
| 嵌套 | 允许嵌套 | 大多一重 |

子分类：
- **外中断** = 可屏蔽中断 + 不可屏蔽中断
- **异常** = 故障 fault + 陷阱 trap + 终止 abort + 编程异常

### 中断响应 4 步（必背）

1. **发现中断源**
2. **保护现场**（PSW、PC、寄存器入栈）
3. **转向处理程序**
4. **恢复现场**

CPU 响应中断的 4 个条件：
- 设置中断请求触发器（有中断请求）
- 设置中断屏蔽触发器允许（屏蔽位为 1）
- CPU 处于开中断状态（IF=1）
- 当前指令执行完

### 中断处理过程（硬件 + 软件协作）

**硬件部分**：
1. 设备发中断信号
2. CPU 当前指令做完才响应
3. 发确认信号
4. 保存上下文（PSW + PC + 寄存器）→ 入核心栈
5. 切到管态，根据中断号查中断向量表 → 跳到处理程序

**软件部分**：
6. 中断处理程序执行
7. 检测到 IRET 指令 → 弹出上下文
8. 恢复 PSW 和 PC → 继续被中断的程序

### 中断向量表

**类比**：像电话本——256 个中断号 = 256 个电话号码 = 256 个处理程序入口。

8086 中断向量表：在内存最前 1KB（00000H ~ 003FFH），256 个向量，每个 4 字节（IP 2 字节 + CS 2 字节），向量地址 = **中断号 × 4**。

Intel x86 256 个向量分配：
- 0~31：异常 + 不可屏蔽中断（固定）
- 32~47：屏蔽中断（外设用）
- 48~255：软中断

### 中断处理程序的 3 大特点

- **异步**：可能打断关键代码甚至其他中断
- **屏蔽态运行**：可能禁止所有中断
- **不能阻塞**：要快速结束（中断上下文里没"进程"概念）

## 2.4 进程的引入

### 为什么需要"进程"这个新概念

**程序**只是静态指令文件（如 `.exe`），它不能描述"正在运行的某次活动"。

**原因 1：刻画并发性**
- 多个程序走走停停穿插执行，"程序"概念太静态
- 进程 = 程序在某数据集上的**一次**计算活动

**原因 2：解决资源共享**
- "可再入程序"（纯代码）能被多人同时调用——同一段程序可对应多个执行实例
- 程序与执行不再一一对应，所以需要"进程"来区分**每次具体执行**

### 进程定义

**进程 = 可并发执行的程序在某数据集合上的一次计算活动，是 OS 进行资源分配和保护的基本单位。**

**做菜类比**：
- **程序** = 菜谱（静态文字）
- **进程** = 你正在按菜谱做的这盘菜（动态过程，有起锅时间、有当前进度、占用某口锅）
- 同一份菜谱可同时被两个人按着做 → 两个独立进程

### 进程的 5 个属性（必背）

| 属性 | 含义 |
| --- | --- |
| **动态性** | 进程是程序的一次执行，有生命周期（创建→运行→消亡） |
| **并发性** | 多个进程可同时存在于内存中，同时间段内推进 |
| **独立性** | 进程是资源分配和调度的基本单位 |
| **异步性** | 各进程以不可预知的速度推进 |
| **结构性** | 每个进程由 PCB + 程序段 + 数据段组成 |

### 进程与程序的区别（必背）

| 对比维度 | 程序 | 进程 |
| --- | --- | --- |
| 本质 | 静态指令序列 | 动态执行活动 |
| 存续 | 可永久存在 | 有生命周期（创建→消亡） |
| 对应关系 | 一个程序可对应多个进程 | 一个进程只能执行一个程序 |
| 组成 | 只是指令和数据 | PCB + 程序段 + 数据段 |

---

## 2.5 PCB（进程控制块）

### PCB 的作用

**PCB 是 OS 感知进程存在的唯一标志**——创建进程 = 建立 PCB，销毁进程 = 删除 PCB。

### PCB 包含的信息

| 信息类别 | 内容 |
| --- | --- |
| 标识信息 | 进程 ID、用户 ID |
| 现场信息 | 寄存器、PC、PSW 等运行时的 CPU 状态 |
| 调度信息 | 状态、优先级、等待时间、已运行时间 |
| 资源信息 | 占用内存、打开的文件、I/O 设备 |
| 链接信息 | 指向下一个 PCB 的指针（队列结构） |

## 2.6 进程状态与转换（必考）

### 三种基本状态

```
┌──────┐     调度选中     ┌──────┐
│ 就绪 │ ──────────────→ │ 运行 │
│Ready │ ←────────────── │Running│
└──────┘  时间片完/抢占   └──────┘
    ↑                        │
    │      I/O 完成/事件     │ I/O 请求/等待事件
    │        发生            │
    │                        ↓
    └────────────────── ┌──────┐
                        │ 阻塞 │
                        │Blocked│
                        └──────┘
```

- **就绪 → 运行**：调度程序选中该进程
- **运行 → 就绪**：时间片用完、被更高优先级进程抢占
- **运行 → 阻塞**：进程请求 I/O 或等待某事件
- **阻塞 → 就绪**：I/O 完成或等待的事件发生

### 五态模型（增加新建态和终止态）

```
新建 (New) → 就绪 (Ready) ↔ 运行 (Running) → 终止 (Terminated)
                    ↑               ↓
                  阻塞 (Blocked)
```

## 2.7 进程切换

### 进程切换的 5 步

1. 保存现场：CPU 寄存器、PC、PSW 保存到 A 的 PCB
2. 入队更新：A 的 PCB 状态改为"就绪"或"阻塞"，挂到对应队列
3. 选择新进程：调度器从就绪队列选中 B
4. 恢复现场：从 B 的 PCB 读出寄存器/PC，写回 CPU
5. 上 CPU：B 的 PCB 状态改"运行"，从 B 的 PC 继续执行

## 2.8 线程

### 为什么引入线程

进程切换开销大（需要切换地址空间、刷新 TLB），而同一进程内多个任务切换频繁。线程是**更轻量级的执行单元**。

### 进程 vs 线程

| 对比维度 | 进程 | 线程 |
| --- | --- | --- |
| 资源拥有 | 独立地址空间 | 共享进程的地址空间 |
| 切换代价 | 大（需切换页表，TLB 失效） | 小（同进程内不切换页表） |
| 通信方式 | IPC（管道、消息队列、共享内存） | 直接读写共享变量 |
| 独立性 | 独立调度单位 | 独立调度单位 |

### 用户级线程 (ULT) vs 内核级线程 (KLT)

| 对比 | 用户级线程 (ULT) | 内核级线程 (KLT) |
| --- | --- | --- |
| 管理者 | 用户空间的线程库 | 内核 |
| 切换代价 | 小（不陷入内核） | 大（需进入内核态） |
| 一个线程阻塞 | 整个进程阻塞（内核不知道有线程） | 只阻塞该线程 |
| 多核利用 | 不能（内核只看到进程） | 可以 |
| 代表 | POSIX Pthreads（用户态实现） | Windows、Linux |

### 混合式线程

- 用户级线程多路复用到内核级线程（m:n 模型）
- Solaris 是典型代表

## 2.9 处理器调度

### 三级调度

| 调度级别 | 别称 | 发生频率 | 任务 |
| --- | --- | --- | --- |
| **高级调度**（作业调度） | 长程调度 | 低（秒级） | 从外存作业池选入内存 |
| **中级调度** | 中程调度 | 中等 | 进程挂起/对换 |
| **低级调度**（进程调度） | 短程调度 | 高（毫秒级） | 从就绪队列选进程上 CPU |

### 调度算法评价指标

- **CPU 利用率** = CPU 忙碌时间 / 总时间
- **吞吐量** = 单位时间完成的进程数
- **周转时间** ti = 完成时刻 - 提交时刻
- **带权周转时间** wi = ti / 运行时间（永远 ≥ 1）
- **平均周转时间** T = Σti / n
- **响应时间**：从提交到第一次响应的时间

## 2.10 七种调度算法（必考计算题）

### 1. FCFS（先来先服务）

| 优点 | 缺点 |
| --- | --- |
| 简单、公平 | 短作业被长作业拖累，平均周转差 |

**典型例题**：作业 P1(0,4)、P2(1,3)、P3(2,5)、P4(3,2)
- 执行顺序：P1→P2→P3→P4
- 平均周转 T = (4+6+10+11)/4 = 7.75
- P4 的带权周转 = 5.5（体现短作业被拖累）

### 2. SJF（短作业优先）

| 优点 | 缺点 |
| --- | --- |
| 平均周转时间最短 | 长作业可能饥饿 |

**非抢占式**：时刻 0 只有 P1 到达 → 先跑 P1，之后选最短的。
- 执行顺序：P1→P4→P2→P3
- 平均周转 T = (4+8+12+3)/4 = 6.75（比 FCFS 优）

### 3. RR（时间片轮转）

| 优点 | 缺点 |
| --- | --- |
| 响应时间短，分时系统首选 | 平均周转比 FCFS/SJF 都差 |

**反直觉**：RR 的 T 和 W 比 FCFS、SJF 都差——因为频繁切换损失了"让短作业快速结束"的机会。

时间片 q 选择：
- q 过大 → 退化为 FCFS
- q 过小 → 切换开销过大

### 4. HRRF（最高响应比优先）

**响应比公式**：R = 1 + 等待时间 / 运行时间

- R 永远 ≥ 1（因为等待时间 ≥ 0）
- 解决了 SJF 的饥饿问题（等久了的作业响应比会升高）

### 5. 优先级调度

- 静态优先级：创建时确定，不变
- 动态优先级：随时间变化（如老化机制）

### 6. 多级反馈队列

- 设置多个就绪队列，不同队列时间片不同
- 进程可在队列间移动
- 兼顾响应时间和周转时间

### 7. 多级队列

- 多个就绪队列，每个队列有自己的调度算法
- 队列间有优先级

## 考点总结

1. **中断**：响应 4 步、分类（外中断 vs 内中断）、硬件+软件协作
2. **进程 vs 程序**：动态 vs 静态，区别表必背
3. **PCB**：OS 识别进程的唯一标志
4. **状态转换**：就绪/运行/阻塞三态转换图（必考）
5. **进程切换 5 步**：保存现场 → 入队 → 调度 → 恢复 → 上 CPU
6. **调度算法计算**：FCFS/SJF/RR/HRRF 的周转时间、带权周转时间计算
7. **线程**：ULT vs KLT 的对比
