## 一、OS 为何存在？

### 核心矛盾

> **硬件是物理的、有限的、慢的；程序是逻辑的、并发的、要快的。**
> OS 就是协调这个矛盾的"大管家"。

### 分层的本质

```
人的视角（用户/程序员）
    ↓
应用软件（Chrome / 微信 / Word ...）
    ↓
操作系统（资源管理 + 接口服务）
    ↓
   ├─ 处理器管理（CPU 调度）
   ├─ 存储管理（内存分配）
   ├─ 设备管理（I/O 控制）
   └─ 文件管理（数据组织）
    ↓
计算机硬件（CPU / 内存 / 磁盘 / 外设）
```

**OS 回答的核心问题链：**

| 问题 | 对应章节 | 矛盾本质 |
| --- | --- | --- |
| 多个程序怎么共用一台 CPU？ | 处理器管理 | CPU 快但只有一个，进程很多 → 怎么切、谁先跑 |
| 多个进程抢同一个资源怎么办？ | 同步互斥与死锁 | 共享变量并发访问 → 竞态条件、死锁 |
| 内存不够用怎么办？ | 存储管理 | 程序想要的内存 > 物理内存 → 虚拟内存 |
| 慢速外设怎么不拖累高速 CPU？ | 设备管理 | CPU GHz 级 vs 外设 ms 级 → 中断/DMA/SPOOLing |
| 操作系统是什么，有什么用？ | 操作系统概论 | 物理硬件太复杂 → 抽象成易用的虚拟机 |

## 三、核心矛盾图谱（每章一个"为什么"）

### 第 1 章：操作系统概论（🎨 涂料）

**矛盾：** 裸机只有 0 和 1，人怎么用？

**核心概念：** OS 定义、四大特性（并发/共享/虚拟/异步）、资源管理三大技术（复用/虚拟/抽象）、系统调用、单内核 vs 微内核

**跨科缝合：** ⛓️ → 计组-指令系统（系统调用的陷入机制）

---

### 第 2 章：处理器管理（🏗️ 梁柱）

**矛盾：** 一个 CPU 怎么同时"服务"多个进程？

**核心冲突链：**
```
CPU 只有一个，进程有 N 个
    → 谁先跑？→ 调度算法（FCFS/SJF/RR/HRRF/优先级/多级反馈队列）
    → 跑到一半被打断怎么办？→ 中断机制 + PCB 保存现场
    → 切来切去太慢怎么办？→ 线程（更轻量的执行单元）
```

**核心概念：** 进程与线程、PCB、中断、状态转换（就绪/运行/阻塞）、七种调度算法、用户级线程 vs 内核级线程

**必背公式：**

| 公式 | 说明 |
| --- | --- |
| 周转时间 ti = tf - ts | 完成时刻 - 提交时刻 |
| 带权周转时间 wi = ti / tk | 周转时间 / 运行时间 |
| 平均周转时间 T = Σti / n | — |
| 响应比 R = 1 + 等待时间 / 运行时间 | HRRF 算法用 |

**致命陷阱：**

| 陷阱 | 说明 |
| --- | --- |
| SJF 的饥饿问题 | 长作业可能永远轮不到 |
| RR 的平均周转比 FCFS 还差 | 频繁切换损失了"快速结束短作业"的机会 |
| 阻塞→运行不存在 | 必须先回到就绪态排队 |

**跨科缝合：** ⛓️ → 计组-中断（中断响应 4 步与 OS 中断处理的协作）

---

### 第 3 章：同步互斥与死锁（🏗️ 梁柱——大题常客）

**矛盾：** 多个进程共享同一资源 → 怎么保证不出错、不死锁？

**核心冲突链：**
```
多个进程共享变量
    → 同时读写 → 竞态条件（结果不唯一）
    → 解决方案：临界区 + 互斥
    → 软件方法（Peterson）/ 硬件方法（TS/Swap/关中断）
    → 信号量 PV 操作（工业标准）
    → 经典问题：生产者-消费者、读者写者、哲学家进餐
    → 资源竞争升级 → 死锁（四个必要条件）
    → 死锁处理：预防/避免（银行家算法）/检测/解除
```

**核心概念：** 临界区、PV 操作、信号量、生产者-消费者、读者写者、哲学家进餐、死锁四条件、银行家算法

**PV 铁律口诀：** 同步 P 在前，互斥 P 在后；P 自己等的，V 别人等的。

**跨科缝合：** ⛓️ → 计组-Cache 一致性（读者写者问题的硬件对应）

---

### 第 4 章：存储管理（🏗️ 梁柱）

**矛盾：** 程序想要的内存 >> 物理内存大小。

**核心冲突链：**
```
程序想要 4GB 地址空间，物理内存只有 512MB
    → 虚拟内存：只把当前需要的部分装入内存
    → 地址转换：逻辑地址 → 物理地址（MMU + 页表）
    → 页太大 → 页表占用太多内存 → 多级页表
    → 页表查询太慢 → TLB（快表）
    → 内存不够 → 页面置换（FIFO/OPT/LRU/Clock）
    → 置换太多 → 抖动（thrashing）
```

**核心概念：** 分页/分段/段页式、页面置换算法、TLB、虚拟内存、工作集

**必背公式：**

| 公式 | 说明 |
| --- | --- |
| 页号 p = INT[A/L], 偏移 d = A mod L | 地址拆分 |
| 物理地址 = 页框号 × L + d | 地址转换 |
| EAT = p × (T_tlb + T_mem) + (1-p) × (T_tlb + 2×T_mem) | TLB 平均访存时间 |
| EAT = (1-f) × T_mem + f × T_缺页 | 缺页平均访存时间 |

**致命陷阱：**

| 陷阱 | 说明 |
| --- | --- |
| Belady 异常 | 只有 FIFO 有——增加页框缺页率反而上升 |
| LRU 命中时移页 | 不是 FIFO，命中时要更新到最新端 |
| 物理地址要算到具体数值 | 不能停在表达式，必须算出数字 |

**跨科缝合：** ⛓️ → 计组-Cache（Cache 映射策略 ↔ 页面置换策略）

---

### 第 5 章：设备管理（🧱 砖墙）

**矛盾：** CPU 太快（GHz），外设太慢（ms）——CPU 怎么等得起？

**核心冲突链：**
```
CPU GHz <-> 外设 ms
    → 轮询（CPU 忙等，浪费）
    → 中断（外设完了通知 CPU，效率提升）
    → DMA（批量传输，只有开始/结束中断 CPU）
    → 通道（I/O 处理机，彻底解放 CPU）
    → 设备太多 → 统一接口（设备独立性）
    → 设备太少 → SPOOLing（虚拟化，共享打印机）
```

**核心概念：** 中断/DMA/通道、磁盘调度（FCFS/SSTF/SCAN/LOOK/C-SCAN）、SPOOLing、I/O 软件四层架构、缓冲技术

**跨科缝合：** ⛓️ → 计组-I/O 方式（DMA 在计组和 OS 中是一致的）

## 四、学习路线

### 推荐顺序

```
第 1 章（涂料）→ 快速扫过，建立全局观
    ↓
第 2 章（梁柱）→ 进程与调度，OS 核心概念
    ↓
第 4 章（梁柱）→ 存储管理，虚拟内存是重点
    ↓
第 3 章（梁柱）→ 同步互斥 + PV 操作 + 死锁，大题主力
    ↓
第 5 章（砖墙）→ 设备管理，I/O 控制方式
```

### 跨科缝合点（与计组联动）

| OS 章节 | 计组章节 | 缝合点 | 建议学习时机 |
| --- | --- | --- | --- |
| 中断机制（Ch2） | 中断与异常 | 中断响应流程 | 学完两者后对比 |
| 页面置换（Ch4） | Cache 替换策略 | LRU/FIFO 的异同 | 同时学，一次搞懂 |
| TLB（Ch4） | Cache | 快表与缓存的命中公式 | 同时学 |
| DMA（Ch5） | I/O 方式 | DMA 传输流程 | 学完两者后对比 |
