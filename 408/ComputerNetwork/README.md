## 一、网络为何存在？

### 核心矛盾

> **一台计算机是孤岛，两台计算机才有价值。**
> 计算机网络就是解决"跨机器的数据如何可靠、高效地传输"的工程实现。

### 分层的本质

```
人的视角（用户 / 浏览器）
    ↓
应用层（HTTP / DNS / SMTP）—— 你关心什么数据
    ↓
传输层（TCP / UDP）—— 数据怎么可靠地到对方
    ↓
网络层（IP / 路由协议）—— 数据走哪条路
    ↓
数据链路层（以太网 / MAC）—— 相邻节点怎么传
    ↓
物理层（光 / 电 / 无线信号）—— 比特怎么在线路上传输
    ↓
物理世界（网线 / 光纤 / 电磁波）
```

**计算机网络回答的核心问题链：**

| 问题 | 对应章节 | 矛盾本质 |
| :--- | :--- | :--- |
| 两台机器怎么传比特？ | 物理层 | 人的 0/1 逻辑 vs 物理信号的编码与调制 |
| 相邻节点怎么确保数据不丢？ | 数据链路层 | 不可靠的物理信道 → 差错控制、流量控制 |
| 数据怎么从源主机到目标主机？ | 网络层 | 网络拓扑复杂 → 路由选择与分组转发 |
| 数据怎么可靠地送到目标进程？ | 传输层 | 网络层不可靠（丢包/乱序/重复）→ 端到端可靠传输 |
| 应用程序怎么使用网络？ | 应用层 | 用户需要具体服务（网页/邮件/文件）→ 应用协议 |

## 三、核心矛盾图谱（每章一个"为什么"）

### 第 1 章：计算机网络体系结构（🎨 涂料）

**矛盾：** 网络太复杂——从物理信号到应用数据，怎么把这么多层组织起来？

**核心概念：** 分层模型（OSI 七层 / TCP/IP 四层）、协议与服务、服务访问点（SAP）、PDU 名称（报文/段/数据报/帧/比特流）

**层间关系（一语中的）：**
```
上层发数据 → 下层封装（加头）→ 物理线路传 →
    下层解封装（去头）→ 上层收数据
```

**核心规律：** 对等层"虚拟通信"（逻辑上和对等层直接对话），但实际上数据是垂直逐层传递的。

**致命陷阱：**

| 陷阱 | 说明 |
| :--- | :--- |
| OSI 与 TCP/IP 分不清 | OSI 是理论模型（7 层），TCP/IP 是实际协议栈（4 / 5 层） |
| PDU 名称乱用 | 应用层=报文（message），传输层=段（segment），网络层=数据报（datagram），链路层=帧（frame） |
| 一层一协议 | 每层有多个协议，不是一一对应 |

### 第 2 章：物理层（🧱 砖墙）

**矛盾：** 人要传的是 0 和 1，但物理线路上只能传模拟信号（电/光/电磁波）——怎么把逻辑比特变成物理信号？

**核心冲突链：**
```
人要传 0101 → 编码（归零/不归零/曼彻斯特）→ 调制（ASK/FSK/PSK）→ 线路传输
    → 但线路有干扰 → 码间串扰 → Nyquist 定理（无噪声极限速率）
    → 还有噪声 → Shannon 定理（有噪声极限速率）
    → 数据要同时双向传输 → 单工/半双工/全双工
```

**核心概念：** 编码与调制、Nyquist 定理（2W log₂V）、Shannon 定理（W log₂(1+S/N)）、香农公式与信噪比（dB）、传输介质（双绞线/同轴/光纤/无线）、信道复用（FDM/TDM/CDMA/WDM）

**必背公式：**

| 公式 | 说明 |
| :--- | :--- |
| 奈氏准则：最大码元率 = 2W（Baud） | 无噪声，受限于带宽 W |
| 香农公式：C = W log₂(1+S/N)（bit/s） | 有噪声，受限于信噪比 |
| dB = 10 log₁₀(S/N) | 分贝与信噪比换算 |
| 比特率 = 波特率 × log₂V | 其中 V 是码元离散电平数 |

**致命陷阱：**

| 陷阱 | 说明 |
| :--- | :--- |
| 奈氏 vs 香农傻傻分不清 | 奈氏是无噪声理想情况，香农是有噪声的实际上限 |
| dB 换算算错 | 30dB → S/N = 1000，不是 30 |
| 波特率 ≠ 比特率 | 只有 2 种电平（log₂2=1）时才相等 |

**跨科缝合：** ⛓️ → 计组-数据表示（曼彻斯特编码与时钟同步思路相通）

---

### 第 3 章：数据链路层（🏗️ 梁柱）

**矛盾：** 物理层只传比特，但比特可能出错、丢失、速率不匹配——相邻节点之间怎么确保数据正确传递？

**核心冲突链：**
```
物理层只传比特 → 但会出错、会丢
    → 封装成帧（加头加尾，区分一条条数据）
    → 差错控制 → 检错（CRC 码）→ 发现错了怎么办？（ARQ 自动重传）
    → 流量控制 → 发送太快接收方来不及收 → 滑动窗口协议
    → 多个设备共享同一链路 → 介质访问控制（MAC）
        → 静态划分（信道复用）
        → 随机接入（CSMA/CD / CSMA/CA）
        → 轮流接入（令牌）
    → 实际链路层技术：以太网（MAC 地址 / 交换机 / VLAN）
    → 不同网络互联 → PPP 协议 / 网桥
```

**核心概念：** 成帧、差错控制（CRC 冗余校验、海明码）、流量控制（停止-等待 / 后退 N 帧 / 选择重传 ARQ）、滑动窗口、CSMA/CD（载波监听多点接入/碰撞检测）、CSMA/CA、以太网帧格式、MAC 地址、交换机（自学习算法）、VLAN、PPP

**必背公式与参数：**

| 公式 / 参数 | 说明 |
| :--- | :--- |
| 最短帧长 = 2 × 传播时延 × 数据传输速率 | CSMA/CD 碰撞检测的关键 |
| 窗口大小 Wₛ ≤ 2ⁿ⁻¹（后退 N 帧） | n 为帧序号位数 |
| 窗口大小 Wₛ ≤ 2ⁿ⁻¹（选择重传） | SR 的窗口大小限制 |
| 链路利用率 = 发送时间 / (发送时间 + 2×传播时延) | 停止-等待协议的效率 |

**致命陷阱：**

| 陷阱 | 说明 |
| :--- | :--- |
| CRC 是检错不是纠错 | CRC 只能"发现"错误，不能定位修正 |
| CSMA/CD 的传播时延 | 不是算"传输时间"，是算"最远两点来回时间" |
| 交换机 vs 集线器 | 交换机隔离冲突域，集线器不隔离 |
| 后退 N 帧 vs 选择重传 | GBN 一错全重传，SR 只重传错的 |

**跨科缝合：** ⛓️ → OS-同步互斥（滑动窗口与流量控制 ↔ 生产者-消费者模型中缓冲区控制）

### 第 4 章：网络层（🏗️ 梁柱——大题常客）

**矛盾：** 数据链路层只能管"相邻节点"，但互联网中数据要从源端跨越无数个中间节点到目的地——数据该走哪条路？

**核心冲突链：**
```
链路层只走"一跳"，网络要走"多跳"
    → 每条数据必须带"目的地" → IP 地址 + IP 数据报格式
    → 路由器怎么知道转发到哪里？ → 路由表 + 路由算法
        → 静态路由 vs 动态路由
        → 距离向量（RIP）："邻居告诉我"，收敛慢
        → 链路状态（OSPF）："我知道全局拓扑"，收敛快
        → BGP：不同自治系统之间
    → 32 位 IP 地址不够用 → 子网划分 + CIDR + NAT
    → 数据报太长怎么办？ → IP 分片与重组
    → 主机怎么知道目标的 MAC 地址？ → ARP 协议
    → 控制层面：ICMP（Ping / Traceroute 都靠它）
    → IPv6：128 位，解决地址枯竭
```

**核心概念：** IP 数据报格式、IP 地址分类（A/B/C）、子网掩码与子网划分、CIDR、NAT、ARP 协议、DHCP、ICMP、路由算法（RIP/OSPF/BGP）、IPv6

**必背公式与操作：**

| 公式 / 操作 | 说明 |
| :--- | :--- |
| 子网数 = 2ⁿ（n=子网号位数） | 全 0/全 1 是否可用？看题目要求 |
| 最大主机数 = 2ʱ - 2（h=主机号位数） | 减去全 0（本网络）和全 1（广播地址） |
| 聚合：取最长公共前缀 | 构成超网，减少路由表条目 |
| 路由转发三步：提取 IP → 查表（最长前缀匹配）→ 下一跳 |

**致命陷阱：**

| 陷阱 | 说明 |
| :--- | :--- |
| 子网划分中全 0 和全 1 | CIDR 下可用，传统分类下不可用——看题目语境 |
| 分片偏移量单位 | 是"8 字节"，不是"1 字节" |
| RIP 的跳数上限 15 | 16=不可达，限制了网络规模 |
| OSPF vs RIP | OSPF 基于 Dijstra，RIP 基于 Bellman-Ford；OSPF 收敛快无环路 |
| MAC 地址在帧头，IP 在数据报头 | 每经过一个路由器，MAC 地址变，IP 不变（除非 NAT） |

**跨科缝合：** ⛓️ → 数据结构-图（路由协议的核心算法 = 图的最短路径问题：RIP↔B-F、OSPF↔Dijkstra）；⛓️ → 计组-总线（路由器转发 ↔ 总线仲裁的"选路"思想）

---

### 第 5 章：传输层（🏗️ 梁柱——大题常客）

**矛盾：** 网络层只负责把数据送到主机，但一台主机上跑着 N 个应用——数据该交给哪个进程？而且网络层可能丢包、乱序、重复——怎么保证端到端可靠？

**核心冲突链：**
```
网络层送到主机（IP 地址），但主机上跑着多个进程
    → 端口号（16 位，区分不同应用）
    → 两个协议任选：
        → UDP：无连接、不可靠、速度快 → 适合流媒体/DNS
        → TCP：面向连接、可靠、有拥塞控制 → 适合网页/文件/邮件
    → TCP 的可靠性靠什么？
        → 序号 + 确认号 → 标定每个字节的位置
        → 超时重传（RTT + RTO 估算）
        → 滑动窗口（接收窗口做流量控制）
        → 拥塞控制（慢开始/拥塞避免/快重传/快恢复）
    → 连接管理：三次握手（建立）→ 四次挥手（释放）
```

**核心概念：** UDP 数据报、TCP 段格式、端口、三次握手、四次挥手、滑动窗口、流量控制、拥塞控制（慢开始/拥塞避免/快重传/快恢复）、超时重传、RTT 估算

**必背公式与参数：**

| 公式 / 参数 | 说明 |
| :--- | :--- |
| 发送窗口 = min(拥塞窗口, 接收窗口) | 实际发送量受两者限制 |
| 慢开始：每轮 cwnd × 2 | 指数增长，直到 ssthresh |
| 拥塞避免：每轮 cwnd + 1 | 线性增长 |
| 超时 → cwnd = 1，ssthresh = cwnd/2 | 慢开始重新开始 |
| 3 个冗余 ACK → 快重传 + 快恢复 | cwnd = ssthresh + 3，不回到 1 |
| 最大报文段寿命 MSL = 2 分钟 | TIME_WAIT 等待 2MSL |

**TCP 三次握手：**

```
CLIENT                    SERVER
  │    SYN=1, seq=x         │
  │ ──────────────────────> │  SYN_RCVD
  │  SYN=1,ACK=1,seq=y,ack=x+1 │
  │ <────────────────────── │
  │  ACK=1,seq=x+1,ack=y+1  │
  │ ──────────────────────> │  ESTABLISHED
  │                         │
```

**致命陷阱：**

| 陷阱 | 说明 |
| :--- | :--- |
| 三次握手的 seq 变化 | SYN 消耗一个序号（所以 ack = x+1），ACK 不消耗 |
| 四次挥手中 FIN 可以带数据 | 收到 FIN 只表示对方不再发，但还可以收 |
| TIME_WAIT 的作用 | 保证最后一个 ACK 到达 + 让旧分组在网络中消散 |
| 拥塞控制 vs 流量控制 | 拥塞控制是"网络太堵了"，流量控制是"接收方太慢了" |
| 快恢复时 cwnd 从哪开始 | 从新的 ssthresh+3 开始，不是从 1 |

**跨科缝合：** ⛓️ → OS-同步互斥（TCP 滑动窗口 ↔ 生产者-消费者协议的缓冲区管理）；⛓️ → OS-死锁（TCP 连接建立与释放的"有限状态机"思路）

### 第 6 章：应用层（🧱 砖墙）

**矛盾：** 传输层提供了端到端传输能力，但用户不关心"怎么传的"——用户要的是网页、邮件、文件、域名解析这些具体服务。

**核心概念：** DNS（域名系统）、HTTP/HTTPS、SMTP/POP3/IMAP（电子邮件）、FTP（文件传输）、DHCP（动态主机配置）、Telnet/SSH

**各协议对比：**

| 协议 | 传输层 | 端口 | 特点 |
| :--- | :--- | :--- | :--- |
| HTTP | TCP | 80 | 无状态、明文 |
| HTTPS | TCP | 443 | HTTP + SSL/TLS 加密 |
| DNS | UDP（大部分） | 53 | 域名 → IP 地址转换 |
| SMTP | TCP | 25 | 发送邮件 |
| POP3 | TCP | 110 | 收邮件（下载后删除） |
| IMAP | TCP | 143 | 收邮件（服务器保留） |
| FTP | TCP | 20(数据)/21(控制) | 控制与数据分离 |
| DHCP | UDP | 67/68 | 自动分配 IP 地址 |

**致命陷阱：**

| 陷阱 | 说明 |
| :--- | :--- |
| HTTP 是无状态的 | Cookie + Session 模拟"有状态"，但协议本身无状态 |
| DNS 使用 UDP | DNS 查询小，一次往返足够；区域传输用 TCP |
| 持久连接 vs 非持久连接 | HTTP/1.0 默认非持久，HTTP/1.1 默认持久 |
| HTTP 方法幂等性 | GET/HEAD/PUT/DELETE 是幂等的，POST 不是 |

**跨科缝合：** ⛓️ → OS-文件管理（FTP 的文件传输 ↔ OS 的文件系统抽象）

## 四、学习路线

### 推荐顺序

```
第 1 章（涂料）→ 快速扫过，建立分层全局观
    ↓
第 3 章（梁柱）→ 数据链路层，理解"相邻节点怎么传"
    ↓
第 4 章（梁柱）→ 网络层，核心：IP + 路由
    ↓
第 5 章（梁柱）→ 传输层，核心：TCP 可靠传输与拥塞控制
    ↓
第 2 章（砖墙）→ 物理层，公式计算为主
    ↓
第 6 章（砖墙）→ 应用层，协议对比记忆
```

### 每章执行 5 步（取自 learning-loop-system.md）

1. **定位矛盾** → 翻开本章前，先问"如果没有这个协议，网络会出什么 bug？"
2. **定级** → 看王道"考情分析"，确定梁柱/砖墙/涂料
3. **预习** → 15 分钟扫标题、图表、加粗定义
4. **精读（三层加工）** → 只对梁柱级做全套
   - L1 结构化：画协议交互图（TCP 三次握手 / 路由表转发流程）
   - L2 关联化：找跨科缝合（标注 ⛓️ 点）
   - L3 模型化：抽象成一句话思维模型
5. **费曼检验** → 用大白话讲给小白听

### 跨科缝合点（提前标注，学到时注意）

| 网络章节 | 缝合科目 | 缝合点 | 建议学习时机 |
| :--- | :--- | :--- | :--- |
| 路由算法（Ch4） | 数据结构 | 最短路径算法（Dijkstra/Bellman-Ford） | 学完两者后，用网络层场景复习图算法 |
| 滑动窗口（Ch3/Ch5） | OS | 同步互斥的缓冲区控制 | 对比链路层 vs 传输层的窗口 |
| 拥塞控制（Ch5） | OS | 资源调度与反馈控制 | 学完两者后对比 |
| 隧道技术（Ch4 IPv6） | OS | 虚拟化思想 | 类似虚拟内存的"封装"思路 |
| DNS 递归查询（Ch6） | 数据结构 | 树与递归 | DNS 查询链 = 树形递归搜索 |
| CSMA/CD（Ch3） | 计组 | 总线仲裁的冲突检测 | 都是"多个设备共享信道"的冲突解决 |

## 五、实操建议（来自 learning-loop-system.md）

### 状态匹配

| 身体状态 | 推荐模式 | 做什么 |
| :--- | :--- | :--- |
| 充满电 | 🔥 满血模式 | 学第 4 章路由 + 第 5 章 TCP 拥塞控制（新知识）、画 IP 分片图 / TCP 状态变迁图 |
| 有点沉 | 🚙 巡航模式 | 刷子网划分计算题、TCP 拥塞窗口大题、背协议端口号 |
| 极度抗拒 | 🛵 苟活模式 | 抄写 TCP 三次握手步骤、默写 OSI 七层列表、抄 IP 数据报格式 |

### 避坑

- ❌ 不要从物理层开始学（全是公式和信号，枯燥且容易劝退）
- ❌ 不要第 4 章和第 5 章同时学（都是梁柱级，脑容量不够）
- ✅ 从第 3 章数据链路层开始是最安全的——概念直观、与生活经验接近
- ✅ 子网划分计算题每天练 2 道，保持手感
- ✅ TCP 拥塞控制的折线图大题几乎年年考——重点掌握慢开始/拥塞避免/快重传/快恢复的 cwnd 变化
